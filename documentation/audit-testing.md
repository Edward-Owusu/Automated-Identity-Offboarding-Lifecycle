# Audit Testing Program

## Audit Objective

Determine whether identity offboarding controls operate effectively enough to prevent separated personnel from retaining unauthorized corporate access beyond the approved SLA.

## AUD-005.1 — Daily Reconciliation

**Test objective:** Compare HRIS separation records against IdP/account-status records.

**Procedure**
1. Obtain the population of separations for the test period.
2. Compare termination timestamps to account-disable timestamps.
3. Identify exceptions exceeding the 24-hour SLA.
4. Inspect exception tickets and documented business justification.
5. Calculate the compliance rate.

**Evidence**
- HR termination event logs
- IdP account-status history
- Reconciliation reports
- Exception tickets

**Frequency:** Daily

**Target:** 100% of separated identities completely offboarded within 24 hours.

## AUD-005.2 — Emergency and Off-Cycle Testing

**Test objective:** Verify rapid removal of active sessions, tokens, and downstream application access.

**Procedure**
1. Select a sample of emergency/off-cycle separations.
2. Trace the event from HR notification through identity suspension.
3. Inspect session/token revocation timestamps.
4. Verify downstream SaaS access removal where applicable.
5. Document exceptions and root causes.

**Evidence**
- OAuth/session revocation logs
- Application access verification
- Ticket timestamps
- Incident or exception records

**Frequency:** Quarterly

**Target:** Zero active corporate sessions or active authorization tokens remaining beyond the defined SLA.

## AUD-005.3 — Integration Health Review

**Test objective:** Assess whether the HRIS-to-IdP integration is reliable, appropriately secured, and governed.

**Procedure**
1. Review connector/API error logs.
2. Identify critical synchronization failures.
3. Review connector privileges and service-account access.
4. Inspect configuration changes.
5. Verify critical errors are remediated within four hours.

**Evidence**
- API error histories
- Integration configuration
- IAM/admin logs
- Change-management tickets

**Frequency:** Semi-Annually

**Target:** 0 critical synchronization errors unresolved for more than four hours.

## Evidence Quality Criteria

Audit evidence should be:

- **Complete** — population or sample is clearly defined.
- **Accurate** — generated by a reliable system or independently corroborated.
- **Timely** — covers the period under review.
- **Traceable** — timestamps and identifiers allow the event to be followed end-to-end.
- **Protected** — sensitive identity information is handled according to organizational policy.
